# CampusRun · 东北大学校园乐跑规划器

一个面向 Windows 的轻量桌面工具：从东北大学 App 的“校园乐跑”小程序读取你的跑步数据，
再按你设置的**目标公里数**与**截止日期**，算出每天需要跑多少、按 2/3/4/5 km 各需要几天，
并生成逐日跑步计划。

> **只读工具**：只读取统计/记录，不提交跑步、不伪造轨迹、不自动刷里程。
> 与学校官方无关，请遵守学校的体育考核规定。

![概览](docs/screenshot-dashboard.png)

## 功能

- **进度读取**：校园乐跑有效次数、累计公里、逐条记录；支持接口只返回汇总字段的情况。
- **每日规划**：剩余里程摊到每个可跑日需要多少 km；今天已跑则自动从明天开始算。
- **完成天数**：每天跑 2 / 3 / 4 / 5 km 分别需要几天、预计哪天完成、离截止日还剩几天。
- **自定义计算**：输入任意每日里程，立即得到天数与完成日期。
- **休息日**：可排除每周固定的休息日（例如周末不跑），可跑日会重新计算。
- **逐日计划**：按 2/3/4/5 km 或自定义里程生成完整日程，一键复制。
- **抓包接入**：粘贴一条 cURL 即可；自动识别记录数组与字段，识别不准可在高级映射里手改。
- **凭据保护**：抓包请求用 Windows DPAPI 加密保存在 `%APPDATA%\CampusRun`，换账户/换机器无法解密。
- **演示模式**：没有抓包数据也能完整体验所有计算功能。
- **CSV 导出**：把逐条记录导出给 Excel。

## 快速开始

要求：Windows 10/11、Python 3.10+（安装时勾选 **Add python.exe to PATH**，并保留 tkinter）。

1. 双击 **`run.cmd`** 启动桌面面板。
2. 首次启动是演示数据，直接可以修改目标、截止日期、休息日，看各种计算结果。
3. 想接入真实账号时，按 [`docs/CAPTURE.md`](docs/CAPTURE.md) 抓一条请求，在“连接设置”页粘贴 cURL，
   点“解析并测试 → 保存连接”。

命令行也可以直接用：

```bat
campusrun.cmd plan
campusrun.cmd plan --target 120 --deadline 2027-01-05 --rest sat,sun
campusrun.cmd plan --done-km 60 --done-runs 20 --json
campusrun.cmd doctor
```

`plan` 不带参数时使用已保存的配置和最近一次数据；没有真实数据时使用演示进度。

## 计算口径

东北大学体育部“校园智慧跑”的公开规则（以学校当期通知为准）：

- 单次有效里程 **2–5 km**；
- 每天最多 **1 条**有效记录；
- 有效配速约 3–10 min/km；
- 每学期里程目标（本工具默认 96 km，可改）。

工具内部约定：

| 概念 | 定义 |
|---|---|
| 已完成 | 有效记录按“每天只取最远一次”去重后累计；接口只给汇总时直接采用汇总 |
| 可跑日 | 今天到截止日（含两端）；如果今天已经有有效记录，则从明天开始；再排除你设置的每周休息日 |
| 每日摊平 | `剩余里程 ÷ 可跑日数`。若结果低于 2 km，会提示“单次至少 2 km，实际按次数安排” |
| 最快天数 | `ceil(剩余里程 ÷ 5)`，每天最多 1 次 |
| “每天 d km” 天数 | `ceil(剩余里程 ÷ d)`；最后一天不足 d 时按剩余量跑（不低于 2 km） |

示例（演示数据）：目标 96 km，已完成 38.4 km（12 次），截止 2027-01-10，今天 2026-10-24：

- 剩余 57.6 km，79 个可跑日，摊平 0.73 km/天；
- 最快 12 天，预计 2026-11-04 完成；
- 每天 2 km → 29 天；3 km → 20 天；4 km → 15 天；5 km → 12 天。

如果剩余里程低于 2 km，场景表仍按 1 天计算，并提示最后一天至少跑 2 km（会略微超额）。

## 连接真实账号

小程序运行在手机上，程序本身无法替你登录。你需要抓一条**已登录状态**的查询请求：

1. 用 Windows 微信打开小程序（最容易成功），或 Android / iOS 抓包；
2. 进入“跑步记录 / 我的里程 / 统计”页，下拉刷新；
3. 找到返回 JSON 里含 `distance`、`totalDistance`、`records` 等字段的请求；
4. 右键 **Copy as cURL**，粘贴到本程序的“连接设置”页；
5. 程序自动请求一次、识别字段、显示次数与公里数；确认无误后保存。

完整步骤、证书配置和常见故障见 **[docs/CAPTURE.md](docs/CAPTURE.md)**。

抓包请求里包含登录令牌，等同于密码：连接文件使用 Windows DPAPI 加密，
请不要把 cURL 原文、预览截图发到公开群聊。令牌过期后重新抓一条覆盖即可。

## 数据与隐私

- 配置、连接、缓存、日志、导出都在 `%APPDATA%\CampusRun`（可用 `CAMPUSRUN_HOME` 覆盖）。
- `connection.dat` 用 DPAPI 加密，只有同一台机器、同一个 Windows 用户可以解密。
- 程序只发送你抓下来的那一条查询请求；不发任何写操作。
- 导出 CSV 只包含日期、里程、用时、配速等记录字段，不包含令牌。
- 工具不收集、不上传任何数据。

## 开发与测试

项目只使用 Python 标准库，不需要安装依赖。

```bat
run_tests.cmd
python tools\ui_smoke.py
python tools\e2e_gui.py
python tools\e2e_cli.py
```

- `ui_smoke.py`：创建窗口、切换四个页面、打开计划弹窗，检查布局不崩。
- `e2e_gui.py`：启动本地 HTTP 服务器模拟校园接口，完整走一遍“粘贴 cURL → 抓取 → 自动识别 → DPAPI 保存 → 重启后刷新”。
- `e2e_cli.py`：用同样的本地接口验证 `import-curl → plan --json → doctor` 的 CLI 链路。
- 测试临时目录固定在 `tests/.tmp`（某些受限环境下 `%TEMP%` 不可写）。

也可以安装为包：

```bat
py -3 -m pip install -e .
campusrun plan --demo
```

## 已知限制

- 真实校园接口的字段需要以你的抓包结果为准；自动识别覆盖常见结构，个别接口需要手工填 JSON 路径或单位。
- 没有实现账号密码登录、验证码、签名算法；只复用你抓到的登录态，令牌过期需要重新抓包。
- 只支持 Windows（DPAPI 与 tkinter 桌面）；核心算法是纯 Python，可移植。
- 尚未打包成单文件 exe；目前以 Python 源码 + `.cmd` 启动。
- 汇总接口若只有总里程、没有“今天是否已跑”，计划会默认今天可跑。
