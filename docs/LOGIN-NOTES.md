# 账号密码自动登录：方案与限制

> 状态：**已实现**（2026-10-24）。
> 账号密码 → CAS → 体育平台 token → 加密 API 已打通；第一个真实账号已验证，
> 第二个账号被 CAS 首次登录引导页拦截，程序会提示用浏览器完成引导。
> 密码只在本地输入，DPAPI 保存。
>
> 不要在任何聊天/公开场合发送真实账号密码。

## 1. 目标（用户澄清后的需求）

用户希望：

1. 在 Windows 本机输入东北大学账号、密码；
2. 程序自动完成登录；
3. 自动拉取“校园乐跑”的次数、公里与记录；
4. 会话过期后自动重新登录，而不是每次抓 cURL。

这与当前“粘贴 cURL 复用登录态”的模式不同，需要新增 **登录协议层**。

## 3. 核心不确定性

“只给账号密码就能全自动登录”是否成立，取决于 **智慧东大 App 自己** 的登录实现：

### 情况 A：App 走学校 SSO，且每次都要短信

- 纯账号密码无法完成登录；
- 只能做“首次账号密码 + 短信验证码”，保存设备信任/会话，之后尽量自动；
- 短信码在手机上，程序无法代替用户接收（除非做 Android 通知/短信读取，侵入性强且不可靠）。

### 情况 B：App 走 SSO，但支持“信任设备”

- 首次登录：账号密码 + 短信 + 勾选信任设备；
- 程序保存设备 cookie / 刷新令牌；
- 后续可用账号密码（或刷新令牌）静默登录，直到设备信任过期。

### 情况 C：App 有独立的账号密码登录 API

- 可能可全自动；
- 仍需知道：登录 URL、密码是否 RSA/AES/MD5、是否有 `sign`/时间戳、token 在响应 JSON 还是 Cookie。

### 情况 D：App 只支持扫码/指纹/已登录会话

- 纯密码登录不可行；
- 只能复用令牌（当前 cURL 模式）或做设备端自动化。

## 4. 需要用户提供的材料（二选一，优先 A）

### A. App 安装包（推荐，不需要给密码）

- 把 `智慧东大` APK 放到工作区，例如 `C:\zwjm\CampusRun\research\zhihui.apk`；
- 或提供可下载的官方链接；
- 我会做静态分析：登录 Activity/JS bridge、API 域名、密码加密、token 字段、短信流程；
- 只做静态分析，不安装、不上传。

### B. 一次登录抓包（不要发密码到聊天）

- 用 mitmproxy/Reqable 抓 App 的登录请求；
- 只需要：请求方法、URL、请求体字段名（密码值可打码/保留加密串）、响应 JSON 结构、Cookie 变化；
- 如果 App 有证书固定/加壳，抓不到就回到 A。

### C. 已登录手机的 token（兜底）

- 从已登录 App 导出 token/Cookie（可能需要 root）；
- 程序用 refresh token 自动续期；
- 这仍是“会话复用”，不是账号密码登录。

## 5. 实现结果（2026-10-24）

已落地代码：

| 模块 | 内容 |
|---|---|
| `neu/crypto.py` | 纯 Python AES-128-CBC、RSA PKCS#1 v1.5、PEM 解析 |
| `neu/cas.py` | CAS 表单解析、RSA 密码、302 链路、短信二次认证、H5 token 解析 |
| `neu/sports.py` | 体育平台 AES/签名、学期/记录/用户信息、分页 |
| `neu/store.py` | `sports_session.dat` / `credentials.dat`（DPAPI） |
| `service.py` | 登录、刷新、token 过期自动重登、与规划缓存集成 |
| `ui/connection.py` | “① 账号登录”卡片：学号/密码/记住密码/登录/退出/短信弹窗；抓包备用默认隐藏，连续失败 2 次显示并提示教程 |
| `cli.py` | `login --remember`、`logout`、`fetch` 自动使用账号会话 |

已用真实 HAR 验证：

- 用 HAR 里的 CASTGC 重新走 `neuLogin` 能拿到新 token；
- token 单独调用 API 成功（无需 Cookie）；
- AES/签名与抓包请求逐字段核对通过；
- 用户 2026-10-24 数据：5 次 / 17.38 km（2026~2027 上学期）。

真实账号验证：

- 第一个账号 `campusrun.cmd login --remember` 成功；
- 第二个账号 CAS 登录后跳到 `tp_tpass/h5?act=tpass/guide` 首次登录引导页，并出现跳转循环；
- 该页面是**首次绑定邮箱**，页面可点“稍后绑定”跳过；纯 HTTP 客户端无法点击页面；
- 程序现在识别该页面；先尝试带会话重新进入 CAS 登录入口，仍被拦截时提示用浏览器打开并点“稍后绑定”；
- 若跳过仍循环，需要抓“稍后绑定”的实际请求/跳转地址再适配。

验证方式：

```bat
campusrun.cmd login --remember
```

输入真实学号/密码；若弹短信就输入验证码。成功后 `campusrun.cmd plan` 会使用真实数据。
失败时把**错误文本**（不要密码/token）反馈即可。若提示“首次登录引导”，
按错误里的 `pass.neu.edu.cn/tp_tpass/h5?...` 地址用浏览器登录该账号并点“稍后绑定”，再重试。

只测试、不保存密码/token/配置：

```bat
campusrun.cmd login --no-save
```

## 6. 安全与合规

- 密码只存本机，DPAPI 绑定 Windows 账户；不写日志、不上传、不放进 cURL/截图。
- 自动登录可能触发学校风控/账号锁定；需要限速、失败退避，并提示用户。
- 只读取跑步统计，不提交跑步、不改成绩。
- 如果学校明确禁止第三方客户端登录，应停止该模式，保留只读 cURL 模式。
